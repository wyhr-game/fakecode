# 摸鱼考：为什么会有"假装在写代码"这种东西

> 这篇不是使用说明，是背景。看不看都不影响用。

---

## 一、摸鱼的四代技术

**第一代：切窗口。**

`Alt + Tab`。历史最久，门槛最低，破绽也最大——老板走过来那 0.8 秒，你能切回去，但鼠标指针还停在一个空的桌面上。

**第二代：假终端。**

跑一个 `while true; do echo; done`，让屏幕上永远有字在滚。看起来在编译，实际上什么都没干。问题是：**编译有终点，你的滚动条没有。** 老练的人看一眼就知道这玩意儿滚了四十分钟还没结束。

**第三代：假编译日志。**

有人写脚本，把一段真实的 build 日志按行重放，带时间戳、带进度条。这个已经很像了。缺点是：**日志是死的，代码不动。** 屏幕上没有光标在走，旁边的人扫一眼编辑区就穿帮。

**第四代：假编辑器。**

屏幕上是真的代码编辑器、真的语法高亮、真的文件树、真的光标在一个字一个字往前走。**它和你平时写代码的样子没有区别，因为它就是在写代码。**

魈公引擎属于第四代。

---

## 二、为什么是"真代码"

市面上大多数同类工具，生成的是随机字符、乱码、或者从模板里抽出来的假代码。

**一眼假。** 因为你同事扫过去的时候，他看的不是内容，是**形状**：缩进、行宽、注释的分布、函数的块状结构。随机字符没有这些形状。

所以这个工具的做法是反过来的：

```
读你指定的目录里真实的 .py 文件
按真实的语法结构分类每一行（导入、声明、注释、控制流、空行）
给不同类别分配不同的"打字耗时"
然后一个字一个字写出来
```

**它写的代码，是你自己项目里的代码。** 复制一份到虚拟文档里，慢慢打出来。原来那份一个字节都没动。

---

## 三、节奏是怎么来的

真正让人"看不出来"的，不是代码内容，是**节奏**。

人类打字有四个特征，机器没有：

```
①  速度不均    同一个词，有时 40ms 一个字，有时 120ms
②  有停顿      想起来下一步要干嘛，停 1~3 秒
③  会打错      打完才发现，退格删掉重打
④  有语义差异  写 import 很快（肌肉记忆），写复杂逻辑很慢（在思考）
```

这个工具把这四条都做了：

```
基线          62ms / 字符
分布          对数正态，σ = 0.42（不是均匀，均匀看起来像机器）
语义系数      import 0.72×、声明 1.8×、注释 0.8×、空行 0.15×、控制流 1.15×
行首缩进      0.45×（敲空格比敲字母快）
标点          1.1~1.5×
每 47 行      一次"思考"，停 120~450ms
每 420 行     一次"走神"，停 3~15 秒
错误率        默认 1.2%
```

**这套数字不是拍脑袋的，是反复调到"录像看不出来"才定下来的。**

而且它用种子（seed）而不是 `Math.random`：同一份代码、同一个种子，每次的节奏完全一样。这既是可复现性，也是一个彩蛋——**你可以给不同的项目配不同的"手速人格"。**

## 四、为什么需要它

说点正经的。

**第一，工位是公开空间，但不该是透明的。**

从背后走过去看一眼屏幕，和盯着你的屏幕看十分钟，是两件事。前者是路过，后者是审查。这个工具解决的是后者——它让你的屏幕在"被扫一眼"的时候，呈现出一个正常人该有的样子。

**第二，有些时候你确实需要"看起来在忙"。**

不是骗人，是**降低沟通成本**。你在等一个 20 分钟的构建、在等同事回消息、在脑子里推一个方案——这些都不产生可见的产出。但你如果盯着空屏幕，就需要向每一个路过的人解释一遍。

**第三，屏幕录制和远程会议。**

录屏的时候光标不动，观众会以为卡了。这不是虚荣，是沟通。

---

## 五、不能拿它干什么

**这条要写清楚，因为工具是中性的，用法不是。**

```
✗  不能用它糊弄交付    代码没写就是没写，光标动一万次也不会编译通过
✗  不能用它骗验收      外包、兼职、按工时结算的活，用它等于诈骗
✗  不能用它掩盖失职    该做的事没做，屏幕再好看也还是没做
✗  不能用来造假证据    录屏"我一直在写"——这是伪证的方向
```

**它是给你喘口气的，不是给你交差的。**

这条界线在你自己心里。工具不会替你划。

---

## 六、三条硬约束

这个项目从第一版起就定了三条规矩，写进代码里，不是写进文档里：

```
1  对源目录只读        没有 write / rename / unlink 任何写操作
2  不在磁盘留东西      目标内容只存在于虚拟文档（VSCode）或内存（桌面版）
3  不联网              没有 fetch、没有 http、没有任何外部请求
```

**为什么？**

因为一个"假装在写代码"的工具，最容易被怀疑的就是：**它会不会偷偷上传我的源码？会不会改我的文件？**

**不会。代码里能查。** 这也是它开源的原因之一——你可以自己看，或者让别人替你看。

---

## 七、一个题外话

写这个东西的过程，比它本身有意思。

你要模拟"人打字"，就得先搞清楚人打字到底长什么样。于是你去翻自己的录屏、去看别人敲键盘的节奏、去数自己在哪一行停顿最久。

**最后发现：人写代码最像人的地方，不是快，是犹豫。**

机器不会犹豫。它要么一次写对，要么报错重来。

**而人会在一行写到一半的时候停住，删掉，换个写法，再停一下。**

这个工具模仿的就是这个。
